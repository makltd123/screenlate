# ScreenLate

[English version](README.md)

ScreenLate — приложение для Android, которое переводит английский текст на экране любого приложения на русский и показывает перевод поверх оригинала. Работает полностью без интернета: перевод делает модель Opus-MT en→ru прямо на телефоне, текст с экрана никуда не отправляется.

## Что уже есть

**Этап 4: OCR.** Приложение находит английский текст в любом приложении и рисует поверх него плашки с русским переводом. Перевод делает модель прямо на телефоне. Для приложений, которые не отдают текст (игры, картинки), есть режим снимка экрана: он распознаёт английский текст и переводит его так же. Полное ТЗ: [docs/SPEC.md](docs/SPEC.md).

Что уже работает:

- служба специальных возможностей, которая читает текст на экране (пароли, поля ввода, клавиатуру и системную шторку не трогает);
- перевод моделью Opus-MT en→ru (около 97 МБ, скачивается один раз при первом запуске, дальше работает без интернета);
- кэш переводов: уже переведённые фразы показываются сразу;
- плашки поверх текста: касания проходят сквозь них, при прокрутке плашки прячутся;
- «Перевести картинку» в меню плавающей кнопки (долгое нажатие): один снимок экрана после разрешения, ожидание остановки картинки, распознавание английского текста ML Kit (офлайн), перевод и плашки поверх; защищённые экраны распознаются и показывают понятное сообщение;
- плитка «ScreenLate» в шторке: включает и выключает перевод;
- мастер настройки и поле «Проверить перевод» на главном экране;
- скрытый экран «Диагностика» (долгое нажатие на номер версии внизу главного экрана) с кнопкой «Проверка модели». Текста с экрана в нём нет.

Чек-лист проверки на телефоне: [docs/CHECKLIST.md](docs/CHECKLIST.md).

Целевой телефон: Realme 10 (4 ГБ ОЗУ), Android 13/14. Минимальная версия Android: 8.0.

## Установка на телефон

### Через Obtainium (рекомендуется для Realme)

На Android 13 и новее приложения, установленные из скачанного APK, не могут включить службу специальных возможностей («доступ ограничен»). На многих телефонах это снимается в «О приложении» → ⋮ → «Разрешить ограниченные настройки», но на Realme такого пункта нет. Приложения, установленные через Obtainium, это ограничение не получают, а Obtainium ещё и сам сообщает о новых версиях.

1. Откройте на телефоне https://github.com/ImranR98/Obtainium/releases/latest и установите APK Obtainium (если файлов несколько, берите тот, где в названии `arm64-v8a`).
2. В Obtainium нажмите **Add App**, вставьте `https://github.com/makltd123/screenlate` и установите ScreenLate.
3. Новые версии потом ставятся из Obtainium кнопкой обновления.

### Из релиза (без дополнительных приложений)

1. Откройте на телефоне страницу [последнего релиза](https://github.com/makltd123/screenlate/releases/latest).
2. Внизу, в разделе **Assets**, нажмите на файл `ScreenLate-<версия>.apk`. Файл скачается.
3. Откройте скачанный файл: из уведомления о загрузке или в приложении «Файлы» → «Загрузки».
4. Если телефон напишет, что установка из этого источника запрещена, нажмите **Настройки** и включите переключатель **Разрешить из этого источника**. Вернитесь назад и нажмите **Установить**.
5. Realme или Google Play Защита могут предупредить, что приложение из неизвестного источника. Это нормально для APK не из магазина: выберите вариант, который продолжает установку (например, **Подробнее** → **Всё равно установить**).

### Из последней сборки (самая свежая версия, нужен вход в GitHub)

1. Откройте [вкладку Actions](https://github.com/makltd123/screenlate/actions/workflows/build.yml) и войдите в GitHub.
2. Нажмите на верхнюю строку с зелёной галочкой.
3. Внизу страницы, в разделе **Artifacts**, нажмите `ScreenLate-<версия>.apk`.
4. Дальше как в шагах 3–5 выше.

Новые версии ставятся поверх старой, без удаления, пока они подписаны одним и тем же ключом (см. ниже).

## Как устроена сборка

APK собирается только в облаке, в GitHub Actions ([`build.yml`](.github/workflows/build.yml)). Это происходит при каждом изменении в ветке `main`, а вручную сборку можно запустить кнопкой **Run workflow** на вкладке Actions.

Шаги: юнит-тесты → сборка release APK → проверка подписи → загрузка APK в раздел Artifacts. Если отправить в репозиторий тег вида `v0.2.0`, workflow дополнительно создаёт релиз с этим APK.

## Ключ подписи

Android разрешает поставить новую версию поверх старой, только если обе подписаны одним ключом. Поэтому ключ создаётся **один раз** и хранится в секретах репозитория. Для этого репозитория ключ уже создан и загружен. Инструкция ниже нужна, если ключ придётся создавать заново (например, для другого репозитория).

> Если ключ потеряется, обновлять приложение поверх старой версии станет нельзя: придётся удалить его и поставить заново. Храните копию файла ключа и паролей в надёжном месте, например в менеджере паролей.

1. На компьютере с Java выполните (вместо `ПАРОЛЬ` придумайте длинный пароль):

   ```
   keytool -genkeypair -storetype PKCS12 -keystore screenlate-release.p12 -alias screenlate -keyalg RSA -keysize 4096 -validity 10000 -storepass ПАРОЛЬ -dname "CN=ScreenLate"
   ```

2. Превратите файл в текст base64. В PowerShell:

   ```
   [Convert]::ToBase64String([IO.File]::ReadAllBytes("screenlate-release.p12")) | Set-Clipboard
   ```

3. На сайте GitHub откройте репозиторий → **Settings** → **Secrets and variables** → **Actions** → **New repository secret** и создайте четыре секрета:

   | Имя | Значение |
   | --- | --- |
   | `KEYSTORE_BASE64` | текст из шага 2 |
   | `KEYSTORE_PASSWORD` | пароль из шага 1 |
   | `KEY_ALIAS` | `screenlate` |
   | `KEY_PASSWORD` | тот же пароль (у формата PKCS12 он совпадает с паролем хранилища) |

4. Запустите сборку заново. В логе шага «Decode signing key» должно быть написано `Signing with the release key from secrets.`

Если секретов нет, сборка всё равно пройдёт, но APK будет подписан временным debug-ключом. Такой APK не ставится поверх предыдущей версии.
