# ТЗ: экранный переводчик для Android (en→ru)

Oct 22, 2026 · @Makltd

## 1. Цель

Сделать Android-приложение, которое переводит английский текст на экране любого приложения на русский и показывает перевод поверх оригинала, почти в реальном времени и полностью офлайн.

- Основной режим: текст берётся через AccessibilityService, перевод рисуется плашками поверх исходных элементов.
- Запасной режим: снимок экрана + OCR для картинок, игр и приложений, которые не отдают текст.
- Перевод делает локальная модель Opus-MT en→ru. Никаких платных API, текст не покидает телефон.
- Рабочее название: **ScreenLate**, пакет `com.screenlate.app` (можно поменять).

## 2. Устройство и ограничения

Целевое устройство: Realme 10 (4G), MediaTek Helio G99, **4 ГБ ОЗУ**, Realme UI на Android 13/14. Приложение должно спокойно работать именно на нём.

| Параметр | Значение |
| --- | --- |
| minSdk | 26 (Android 8.0) |
| targetSdk / compileSdk | 34 |
| ABI | arm64-v8a (только он, чтобы не раздувать APK) |
| Язык | en → ru |
| Сеть | только для однократной загрузки модели |

- У владельца **нет Android Studio**. Весь проект собирается в облаке через GitHub Actions, APK скачивается из артефактов сборки.
- Нельзя полагаться на ручные действия в IDE: всё, что нужно для сборки, должно быть в репозитории и в workflow.
- Realme UI агрессивно убивает фоновые службы. Приложение должно провести пользователя через настройки автозапуска и батареи (см. F8).

## 3. Технологический стек

| Часть | Решение |
| --- | --- |
| Язык и сборка | Kotlin, Gradle Kotlin DSL, version catalog |
| Асинхронность | Kotlin Coroutines + Flow |
| UI настроек | Jetpack Compose (Material 3) |
| Чтение экрана | `AccessibilityService` |
| Оверлей | `WindowManager` с `TYPE_ACCESSIBILITY_OVERLAY` (не нужно разрешение «поверх других окон») |
| Модель перевода | Helsinki-NLP `opus-mt-en-ru` (MarianMT), экспорт в ONNX, int8-квантование |
| Движок | ONNX Runtime Android (`com.microsoft.onnxruntime:onnxruntime-android`) |
| Токенизатор | SentencePiece (`source.spm`, `target.spm`, `vocab.json` из модели) |
| Кэш | LRU в памяти + Room (SQLite) на диске |
| OCR (этап 4) | ML Kit Text Recognition, латиница, вариант bundled. Только распознавание, переводит по-прежнему Opus-MT |
| Хранение настроек | DataStore |

Детали по модели:

- Экспорт: Hugging Face Optimum (`optimum-cli export onnx`), получить encoder и decoder с KV-кэшем (предпочтительно `decoder_model_merged.onnx`), затем динамическое int8-квантование через `onnxruntime.quantization`.
- Генерация: greedy-декодирование в Kotlin с KV-кэшем, лимит длины \~1.5× входа + 10 токенов. Beam search не нужен.
- Токенизация SentencePiece: собрать нативную библиотеку sentencepiece через NDK/CMake с тонкой JNI-обёрткой. Если это окажется слишком тяжело, допустим чистый Kotlin-токенизатор unigram с проверкой на совпадение с Python.
- Модель **не кладётся в APK**. Отдельный workflow конвертирует её и выкладывает в GitHub Release, приложение скачивает её при первом запуске и проверяет SHA-256.
- План Б, если ONNX-экспорт Marian не заведётся: движок Bergamot (Mozilla Firefox Translations) с моделью en→ru. Переходить на него только после согласования с владельцем.

## 4. Функциональные требования

**F1. Сбор текста с экрана (AccessibilityService)**

- Подписка на события: `TYPE_WINDOW_STATE_CHANGED`, `TYPE_WINDOW_CONTENT_CHANGED`, `TYPE_VIEW_SCROLLED`, `TYPE_VIEW_TEXT_CHANGED`.
- Обход дерева `rootInActiveWindow` (и `windows`, если доступно), сбор узлов с непустым `text` или `contentDescription`, видимых на экране, с координатами `getBoundsInScreen`.
- Фильтр: только английский текст (доля латинских букв > 60%, минимум 2 буквы). Пропускать числа, URL, e-mail, время, одиночные символы.
- Никогда не трогать: поля паролей (`isPassword`), собственное приложение, системный UI, клавиатуру, приложения из списка исключений.
- Редактируемые поля (`isEditable`) по умолчанию не переводить, опция в настройках.
- Debounce 250 мс после последнего события перед запуском перевода.

**F2. Оверлей с переводом**

- Один полноэкранный слой `TYPE_ACCESSIBILITY_OVERLAY` с флагами `FLAG_NOT_TOUCHABLE` и `FLAG_NOT_FOCUSABLE`. Оверлей **никогда** не перехватывает касания.
- Для каждого переведённого узла рисуется плашка ровно по его границам.
- Режимы отображения: «Заменить» (непрозрачная плашка закрывает оригинал), «Поверх» (полупрозрачная, прозрачность настраивается), «Подсказка» (маленькая плашка под оригиналом).
- Цвет плашки следует светлой/тёмной теме системы.
- Подгонка шрифта: автоуменьшение до минимума 8 sp (настраивается), чтобы перевод влез в границы. Не влезает даже так — обрезка с многоточием, полный текст по долгому нажатию на плавающую кнопку.
- Во время скролла и смены окна плашки скрываются сразу, появляются через 300 мс после остановки.
- Плашки, чей узел исчез или сдвинулся, удаляются. Мерцания при перерисовке быть не должно (переиспользовать view, diff по ключу узла).

**F3. Перевод**

- Очередь с приоритетом видимых на экране элементов. При смене экрана устаревшие задачи отменяются.
- Длинные тексты режутся на предложения, переводятся по отдельности и склеиваются.
- Пакетная обработка: несколько коротких фраз за один прогон энкодера, если это ускоряет работу.
- Кэш: ключ — нормализованный исходный текст. В памяти LRU на 2000 записей, на диске до 20 МБ с вытеснением старых. Кэшированный перевод показывается сразу.
- Регистр и форматирование (переносы строк, маркеры списков) по возможности сохраняются.

**F4. Плавающая кнопка**

- Маленький круглый «пузырь» поверх экрана, перетаскивается, прилипает к краю.
- Нажатие — включить или выключить перевод. Долгое нажатие — меню: режим отображения, «Перевести картинку (OCR)», пауза для этого приложения, открыть настройки.
- Кнопку можно скрыть, если включена плитка в шторке.

**F5. Плитка в шторке (Quick Settings Tile)**

- Включение и выключение перевода, иконка показывает состояние.

**F6. Режим OCR (этап 4)**

- Запуск только по кнопке, не постоянно. Разрешение `MediaProjection` запрашивается при первом использовании за сессию.
- Foreground service с типом `mediaProjection` и уведомлением.
- Один снимок экрана после того, как изображение перестало меняться, затем распознавание (ML Kit, по блокам и строкам с координатами), перевод, плашки поверх. Повторный снимок только по новому нажатию.
- Экраны с `FLAG_SECURE` дают чёрный снимок — показать понятное сообщение.

**F7. Настройки**

- Вкл/выкл, режим отображения, прозрачность, минимальный размер шрифта.
- Список исключённых приложений (поиск по установленным).
- Режим «Экономия»: перевод только по нажатию на кнопку, без автоматического отслеживания.
- Число потоков модели: 2 (по умолчанию) или 4.
- Статус модели: загружена или нет, размер, кнопка «Загрузить заново», «Очистить кэш».
- Тестовое поле: ввести английский текст и сразу увидеть перевод и время.

**F8. Первый запуск и разрешения**

- Пошаговый мастер на русском: загрузка модели, включение службы специальных возможностей, уведомления.
- Android 13+: объяснить шаг «Разрешить ограниченные настройки» (свойства приложения → меню ⋮), так как APK установлен не из магазина.
- Запрос исключения из оптимизации батареи (`ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`) и инструкция для Realme: автозапуск, «Разрешить фоновую активность», закрепить приложение в недавних.
- Каждый шаг показывает, выполнен он или нет, с кнопкой перехода в нужный экран настроек.

## 5. Нефункциональные требования

Целевые значения измеряются на Realme 10 (4 ГБ). Если цель не достигается, сообщить фактические цифры, а не подгонять тесты.

| Метрика | Цель |
| --- | --- |
| Показ перевода из кэша | < 50 мс |
| Новая короткая фраза (до 10 слов) | < 300 мс |
| Экран из 20 новых фраз | < 2 с до появления всех плашек |
| Память всего процесса | < 300 МБ в режиме AccessibilityService |
| Размер APK без модели | < 30 МБ |
| Размер модели (int8) | ориентир 80–120 МБ |
| Холодная загрузка модели | < 3 с |

**Батарея**

- Перевод запускается только по событиям изменения экрана, никаких таймеров и опроса.
- При выключенном экране (`ACTION_SCREEN_OFF`) вся работа останавливается, сессия ONNX выгружается через 5 минут простоя.
- OCR не работает в фоне, только по нажатию.
- Модель на 2 потоках по умолчанию.

**Приватность**

- Текст с экрана не отправляется в сеть и не пишется в логи release-сборки.
- Единственный сетевой запрос — загрузка модели по фиксированному URL с проверкой SHA-256.
- Разрешение `INTERNET` есть только для этого. Никакой аналитики и рекламы.
- Дисковый кэш можно очистить одной кнопкой.

**Надёжность**

- Ошибка модели или оверлея не должна ронять службу: перехват исключений, понятный статус в уведомлении и настройках.
- После перезагрузки телефона служба поднимается сама (если система это позволяет).

## 6. Архитектура

Один модуль `app`, внутри разделение по пакетам. Движок перевода изолирован за интерфейсом, чтобы его можно было заменить (ONNX → Bergamot) без правок остального кода.

Поток данных:

1. `ScreenTextCollector` получает событие, ждёт 250 мс тишины и собирает список `TextItem(key, text, bounds, packageName)`.
2. `TextFilter` отбрасывает не английское, пароли, исключённые приложения.
3. `TranslationRepository` отдаёт перевод из кэша или ставит задачу в очередь `TranslationQueue`.
4. `Translator` (интерфейс) → `OnnxMarianTranslator`: токенизация, энкодер, greedy-декодер, детокенизация.
5. `OverlayRenderer` делает diff с текущими плашками и обновляет только изменившиеся.

Структура пакетов:

```
app/src/main/java/com/screenlate/app/
  accessibility/   ScreenTranslateService, ScreenTextCollector, TextFilter
  overlay/         OverlayRenderer, PlaqueView, FloatingBubble, AutoFitText
  translate/       Translator, OnnxMarianTranslator, MarianTokenizer, TranslationQueue
  cache/           TranslationRepository, LruMemoryCache, TranslationDao, AppDatabase
  model/           ModelManager (загрузка, SHA-256, распаковка, статус)
  ocr/             OcrCaptureService, ScreenshotGrabber, OcrRecognizer (этап 4)
  tile/            TranslateTileService
  settings/        SettingsRepository (DataStore)
  ui/              MainActivity, OnboardingScreen, SettingsScreen, TestTranslateScreen
app/src/main/cpp/  sentencepiece JNI (если выбран нативный вариант)
scripts/           convert_model.py, reference_translate.py
.github/workflows/ build.yml, convert-model.yml
```

## 7. Сборка через GitHub Actions

APK собирается только в облаке. Владелец скачивает его из артефактов или релиза прямо на телефон.

**`build.yml`** — на каждый push в `main` и вручную (`workflow_dispatch`):

- `ubuntu-latest`, JDK 17, `gradle/actions/setup-gradle` с кэшем, Android SDK и NDK из образа раннера.
- Gradle Wrapper должен быть в репозитории полностью (`gradlew`, `gradle-wrapper.jar`, `gradle-wrapper.properties`). Если сгенерировать jar локально нельзя, workflow сам выполняет `gradle wrapper` перед сборкой.
- Шаги: юнит-тесты → `assembleRelease` → загрузка APK как artifact с понятным именем (`ScreenLate-<версия>.apk`).
- Подпись: если в Secrets есть `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD` — подписывать ими. Если нет — подписывать debug-ключом, чтобы APK всё равно ставился. Важно: для обновления поверх старой версии ключ должен быть один и тот же, в README описать, как один раз создать keystore.
- На тег `v*` — создавать GitHub Release с APK.

**`convert-model.yml`** — запускается вручную:

- Python 3.11, `optimum[onnxruntime]`, `transformers`, `sentencepiece`.
- `scripts/convert_model.py`: экспорт `Helsinki-NLP/opus-mt-en-ru` в ONNX, int8-квантование, проверка перевода 20 эталонных фраз, упаковка в zip (onnx-файлы, `source.spm`, `target.spm`, `vocab.json`, `config.json`), расчёт SHA-256.
- Публикация zip в GitHub Release с тегом `model-v1`. URL и хэш прописываются в `ModelManager` (через `BuildConfig`).

## 8. Этапы и критерии приёмки

Каждый этап заканчивается рабочим APK из GitHub Actions. Следующий этап начинается только после того, как владелец проверил предыдущий на телефоне.

1. **Этап 0. Каркас и CI.**
   - Пустой проект, экран «Hello», `build.yml`, `README.md` на русском с инструкцией установки.
   - Приёмка: APK скачивается из Actions и ставится на Realme 10.
2. **Этап 1. Служба и оверлей с заглушкой.**
   - F1, F2, F5, F8 (мастер разрешений). Вместо перевода — заглушка: исходный текст в квадратных скобках с префиксом `RU:`.
   - Приёмка: в Chrome, Telegram и Настройках плашки стоят точно на месте текста, касания проходят сквозь оверлей, при скролле плашки прячутся.
3. **Этап 2. Настоящий перевод.**
   - `convert-model.yml`, `ModelManager`, `OnnxMarianTranslator`, токенизатор, кэш (F3), тестовое поле в настройках.
   - Приёмка: 20 эталонных фраз переводятся так же, как в Python-эталоне; время и память укладываются в таблицу из раздела 5.
4. **Этап 3. Удобство и полировка.**
   - F4 (плавающая кнопка), F7 (все настройки), режимы отображения, подгонка шрифта, исключения, режим «Экономия».
   - Приёмка: сценарий «полистать англоязычную статью в Chrome 5 минут» без мерцания, вылетов и залипших плашек.
5. **Этап 4. OCR.**
   - F6.
   - Приёмка: скриншот с английским текстом и англоязычная игра переводятся по нажатию за < 2 с.
6. **Этап 5. Оптимизация батареи и памяти.**
   - Замеры, профилирование, подбор debounce и числа потоков.
   - Приёмка: час чтения в режиме AccessibilityService заметно не отличается по расходу от обычного использования (сверка в «Настройки → Батарея»).

## 9. Тестирование

У владельца нет эмулятора и IDE, поэтому всё, что можно проверить без телефона, проверяется юнит-тестами в CI.

- **Юнит-тесты (JVM):** `TextFilter` (английский/не английский, пароли, URL), LRU-кэш, нарезка на предложения, diff плашек, подгонка шрифта (расчёт размера).
- **Токенизатор:** для 50 фраз id токенов совпадают с Python `MarianTokenizer`. Эталон генерирует `scripts/reference_translate.py` и кладёт в `src/test/resources`.
- **Перевод:** проверка в `convert-model.yml` на Python ONNX Runtime — 20 эталонных фраз совпадают с оригинальной PyTorch-моделью (допускается расхождение в 1–2 словах после квантования).
- **Ручной чек-лист для владельца** (положить в `docs/CHECKLIST.md` на русском): Chrome, Telegram, YouTube (описания), Reddit, системные настройки, Google Play; тёмная тема; поворот экрана; блокировка и разблокировка; перезагрузка телефона.
- **Отладка на телефоне:** в настройках скрытый экран «Диагностика» — последние 50 событий службы, время перевода, размер кэша, потребление памяти. Без самого текста экрана.

## 10. Риски и ограничения

| Риск | Что делать |
| --- | --- |
| Экспорт Marian в ONNX с KV-кэшем капризный | Начать с `decoder_model_merged`; если не выходит — отдельные `decoder_model` и `decoder_with_past_model`; крайний случай — план Б (Bergamot) по согласованию |
| SentencePiece на Android требует NDK | Собрать через CMake в CI; запасной вариант — Kotlin-реализация unigram с тестом на совпадение |
| Realme UI убивает службу | Мастер F8, foreground-уведомление по желанию, проверка состояния при каждом открытии приложения |
| Некоторые приложения не отдают текст (игры, Flutter, Canvas, банки) | Это ожидаемо, для них режим OCR |
| Границы узла — прямоугольник, а не строки | Плашка закрывает весь прямоугольник; для многострочного текста допустимо |
| Перевод длиннее оригинала на 15–20% | Подгонка шрифта, затем обрезка с многоточием |
| Защищённые экраны (`FLAG_SECURE`) | OCR даёт чёрный снимок — сообщение пользователю |
| 4 ГБ ОЗУ | Одна сессия ONNX, выгрузка в простое, без LLM |

Не входит в задачу: другие языковые пары, синхронизация, облачные API, iOS, перевод речи.

## 11. Правила для Claude Code

- Сначала прочитай всё ТЗ, затем составь план этапа и покажи его. Работай строго по этапам из раздела 8, не забегай вперёд.
- После каждого этапа: коммит, push, убедиться, что `build.yml` прошёл зелёным, и коротко на русском написать, что проверить на телефоне.
- Не меняй стек (раздел 3) и не добавляй сетевые запросы без согласования с владельцем.
- Если что-то не получается за 2–3 попытки (особенно ONNX-экспорт и SentencePiece) — остановись и опиши проблему и варианты, а не обходи требования молча.
- Не выдумывай версии библиотек: проверяй актуальные стабильные версии перед добавлением зависимостей.
- Код и комментарии в коде на английском. Весь интерфейс, README и чек-листы — на русском.
- Владелец не программист в Android и не имеет IDE: любые инструкции для него — пошагово, с телефона или через сайт GitHub.
- Не логируй текст с экрана нигде, кроме debug-сборки.
- Это ТЗ положи в репозиторий как `docs/SPEC.md`, а в `CLAUDE.md` — краткую выжимку правил из этого раздела и ссылку на спецификацию.
